# 0G — Private Computer

The primary scanner supports evidence-grounded 0G inference after deterministic analysis. The application uses the official documented Router protocol through server-side fetch rather than inventing a Private Computer SDK. This avoids the macOS/Linux-only onboarding CLI on the Windows host while retaining the documented API path.

Endpoint: https://router-api.0g.ai/v1/chat/completions; private/verified routing header, verify_tee, structured JSON, actual x_0g_trace.request_id, Router TEE result and ZG-Res-Key provenance are handled. The model must be configured from the live account catalog. Unknown IDs or malformed evidence references are rejected. No automatic model substitution or fabricated response exists.

Without 0G, deterministic scanning still works, but the evidence-grounded explanation/inference provenance component of a full passport is unavailable. The disabled UI control and request record say so explicitly. Repeat scans create new evidence payloads to explain changed findings.

The user authorizes existing free credits only. API key/model are absent, so no inference has been sent. The live-inference sponsor requirement remains **BLOCKED**, not complete. Browser control was unable to verify the active Chrome URL and stopped before account access; no API key was created or extracted.

Router-reported tee_verified is not independent attestation. Independent verification remains NOT_PERFORMED. Private trust mode is a request configuration, not an unsupported claim that a particular execution was private.
